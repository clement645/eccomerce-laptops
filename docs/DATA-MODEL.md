# Initial data model

Implemented in Phase 2 in [packages/database/prisma/schema.prisma](../packages/database/prisma/schema.prisma) (46 tables). This document is the design summary; the schema is authoritative.

Changes made while implementing: payments use their own `PaymentRecordStatus` enum (separate from the order's `PaymentStatus`); `HomepageSectionItem` holds curated products per homepage section; `Cart.guestTokenHash` stores only a hash of the guest cookie; `PaymentAttempt` stores a masked phone number only; table names are snake_case plural while columns keep Prisma's camelCase.

Conventions:

- IDs are UUID v7 (`@db.Uuid`, time-ordered, so index-friendly and unguessable enough for internal use). Public tracking uses a separate random token.
- Every table has `createdAt` and `updatedAt`. Soft-deletable catalog tables have `archivedAt`.
- Money is `Int` in KES minor units (cents), with `CHECK (x >= 0)`.
- Enums are Postgres enums, mirrored in `@repo/shared-types`.

Fulfilment state machine (enforced in `OrdersService`):

```text
PENDING → PROCESSING → PACKED → SHIPPED → DELIVERED
   │           │          │
   └───────────┴──────────┴──► CANCELLED   (cannot cancel after SHIPPED; use returns)
```

Payment status: `UNPAID → PENDING → PAID → (PARTIALLY_REFUNDED | REFUNDED)`, plus `FAILED`. COD orders stay `UNPAID` until delivery is confirmed.
